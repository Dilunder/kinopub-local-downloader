# KinoPub Local Downloader

Локальный менеджер загрузок на русском: FastAPI, SQLite/SQLAlchemy, Jinja2,
HTMX, Alpine.js и Tailwind CDN. Видео скачивает отдельный процесс yt-dlp с
плагином yt-dlp-kinopub. Node.js для установки и запуска не нужен.

## Быстрый запуск

Для Windows также подготовлена сборка **одним EXE**, без установки Python,
pip и ffmpeg. Скачайте `KinoPub-Local-Downloader.exe` из **Assets** нужного
GitHub Release и запустите двойным щелчком. Откроются небольшое окно
управления и интерфейс в обычном браузере. Для остановки используйте
«Остановить и закрыть» в окне приложения.

Настройки EXE сохраняются в `%LOCALAPPDATA%\KinoPubLocalDownloader\data`,
видео по умолчанию — в `%USERPROFILE%\Downloads\KinoPub`. При обновлении
достаточно заменить EXE: настройки остаются. Данные Python-версии из `data/`
автоматически не переносятся. Python, yt-dlp, плагин, ffmpeg и ffprobe
находятся внутри файла; при запуске они распаковываются во временную папку.
Поэтому первый запуск занимает время, а размер EXE существенно больше
архива исходников. Интерфейс использует браузер; отдельный браузерный движок
не встраивается.

EXE слушает только 127.0.0.1. Начальный порт 8000, при занятости выбирается
свободный 8001–8010. Повторный запуск открывает работающий экземпляр.

Ниже остаются команды для запуска **из исходников**.

Нужны Python **3.11+** и системный **ffmpeg** в `PATH`.

Windows PowerShell, из папки проекта:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
# Если ffmpeg ещё не установлен:
winget install --id Gyan.FFmpeg --exact
# После установки ffmpeg откройте новый терминал.
ffmpeg -version
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

В этой рабочей папке уже создана `.venv` с зависимостями. Достаточно последней
команды, если окружение осталось на этом компьютере. ffmpeg установлен через
WinGet; в новом терминале он будет доступен в PATH. Системные ярлыки `python`
и `py` здесь при проверке не работали; окружение создано доступным Python 3.12.
Не переносите `.venv` на другой компьютер: пересоздайте его обычным Python.

Linux/macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
# Debian/Ubuntu: sudo apt install ffmpeg
# macOS: brew install ffmpeg
ffmpeg -version
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте **http://127.0.0.1:8000**. Используйте именно `127.0.0.1`, не `localhost`.
Остановка — `Ctrl+C`. Один процесс Uvicorn; не используйте `--workers` больше 1.
Блокировка папки `data` предотвращает запуск двух воркеров на одной БД.

Не указывайте `--host 0.0.0.0`, не ставьте reverse proxy, не публикуйте сервис.
Проверка localhost в приложении дополняет привязку Uvicorn к loopback, но не
заменяет её. Доступ для других пользователей вашего компьютера не изолирован.

## Первый запуск и cookies

1. Откройте **Настройки**. Укажите корневую папку загрузок; по умолчанию это
   `downloads/` рядом с README. Папка создаётся при сохранении.
2. Для браузера выберите источник «Из браузера» и браузер, в котором вы сами
   вошли на kino.pub / kino.watch. По умолчанию выбран Firefox. Перед чтением
   cookies может потребоваться закрыть браузер. Поддержка зависит от ОС,
   шифрования профиля и возможностей установленного yt-dlp.
3. Альтернатива — экспортируйте **свои** cookies в Netscape cookies.txt.
   Образец структуры с вымышленными значениями доступен по ссылке
   «Скачать пример cookies.txt» рядом с выбором файла в настройках.
   В каждой записи 7 полей, разделённых настоящими символами табуляции:
   домен, поддомены TRUE/FALSE, путь, HTTPS TRUE/FALSE, Unix-срок действия,
   имя cookie, значение. Имена и значения реальных cookies берите из экспорта
   своего браузера; учебный пример не авторизует аккаунт.
   Загрузите через кнопку в настройках. Источник «Файл cookies.txt» теперь
   включается и сохраняется автоматически; остальные изменения формы
   сохраняются общей кнопкой. Пароли от аккаунта сервис не запрашивает.
4. Загрузка файла сохраняет только записи доменов kino.pub / kino.watch
   (включая www), до 1 МБ. Файл находится в `data/cookies.txt`; его содержимое
   не возвращается API. На POSIX устанавливаются права `0600` (каталог data —
   `0700`). На Windows перед записью файла сервис удаляет наследуемые NTFS ACL
   и предоставляет доступ только SID текущего пользователя. Администратор ОС
   всё равно может получить доступ; используйте отдельную учётную запись на общем ПК.
5. Укажите качество, предпочтительный язык/студию, языки субтитров через запятую
   (`ru,en`) или `all`; пустое поле отключает субтитры. Сохраните.

Плагин читает cookies через стандартные параметры yt-dlp
`--cookies-from-browser <browser>` или `--cookies <file>`.
Конфигурация yt-dlp пользователя игнорируется (`--ignore-config`), его кэш
отключён (`--no-cache-dir`). Сервис не использует сохранённые сторонние
API-токены, netrc, OAuth-секреты и произвольные extractor-аргументы.

## Использование

### Открытый Edge/Chrome: импорт Cookie без чтения базы браузера

На Windows браузер может удерживать файл cookies заблокированным. Если
интерфейс приложения открыт в этом же Edge, автоматическое чтение его
базы yt-dlp может завершиться `Could not copy Chrome cookie database`.
Сообщение yt-dlp общее для Chromium-браузеров, включая Edge.

В версии 0.2.1 добавлен импорт действующей сессии:

1. В настройках раскройте **«Вставить Cookie из браузера»**.
2. На странице KinoPub, где вы вошли в свой аккаунт, откройте F12 →
   **Network / Сеть** и обновите страницу.
3. Выберите запрос к домену сайта → **Headers → Request Headers → Cookie**.
   Скопируйте значение этого заголовка полностью.
4. В приложении выберите домен, вставьте Cookie в скрытое поле. При
   необходимости скопируйте **User-Agent** из тех же Request Headers.
5. Нажмите **«Сохранить Cookie»**. Приложение создаст защищённый Netscape
   файл и сразу переключит источник на него. Браузер можно оставить открытым.

Значение очищается из поля после успешного сохранения, не возвращается API,
не включается в логи или Git. Поля Cookie нет в обычном запросе сохранения
настроек. Сессия принадлежит вашему аккаунту; когда она истечёт, повторите
импорт. Автоматическое чтение браузера также остаётся доступным. Для него
может понадобиться полностью закрыть выбранный браузер и открыть интерфейс
в другом. Современное шифрование Chromium может ограничивать расшифровку
даже при закрытом браузере — тогда используйте импорт или cookies.txt.

Для загрузки напрямую из поддерживаемых профилей Chromium включён
PyCryptodomex. Приложение не отключает защиту браузера, не завершает его
процессы и не устанавливает плагины разблокировки базы.

### Добавление загрузки

- На главной вставьте ссылку вида `https://kino.watch/item/view/123`.
  Допускаются kino.pub, kino.watch и их www-варианты, HTTP(S), стандартные порты.
  Для отдельного эпизода: `/item/view/123/s1e2`. Параметры запроса, фрагменты,
  учётные данные в URL и другие домены запрещены.
- «Получить информацию» читает название, плейлист эпизодов, качества,
  доступное аудио и субтитры. Это полный запрос метаданных: большие сериалы
  могут обрабатываться долго (таймаут по умолчанию 180 секунд).
- Выберите максимальное качество. Если его нет, yt-dlp выбирает лучшее
  доступное **не выше указанного**. Настройка «Лучшее» не ограничивает высоту.
- Аудио выбирается предпочтением плагина: подстрока студии или код языка.
  При отсутствии совпадения плагин оставляет дорожку по умолчанию. Состав
  дорожек у разных эпизодов может различаться. Ввод поддерживает безопасный
  ограниченный набор символов; сложные названия можно указать подстрокой.
- Предпросмотр показывает сведения, которые действительно вернул плагин.
  Отсутствующие дорожки/субтитры не придумываются. Постеры и подписанные URL
  потоков не загружаются в браузер и не сохраняются в БД.
- По умолчанию скачивается весь сериал. Можно отметить нужные эпизоды;
  в yt-dlp передаются их **позиции в плейлисте**, начиная с 1.
- Подпапка задачи относительна корню загрузок: `Сериалы/Вечер`. Переходы
  `..`, абсолютные пути, диски, управляющие символы и выход через symlink
  запрещены. Корневую папку можно явно изменить только в настройках.
- Шаблон задаёт только имя файла. Поддерживаются `title`, `id`, `ext`,
  `series`, `season_number`, `episode_number`, `playlist_index`, преобразования
  `s`/`d` с числовой шириной. Пример для эпизодов:
  `S%(season_number)02dE%(episode_number)02d - %(title)s [%(id)s].%(ext)s`.
  Используйте `id` или `playlist_index`, чтобы избежать совпадения имён.
- Результат — MKV: ffmpeg склеивает/перепаковывает потоки без перекодирования,
  при наличии встраиваются выбранные субтитры. Уже существующие файлы не
  перезаписываются. Частичные `.part` остаются для докачки.
- Прогресс отображает текущий поток/файл. При переходе к аудио или следующей
  серии процент может начинаться заново; это **не общий процент сериала**.
- Отмена завершает процесс yt-dlp и дочерние процессы ffmpeg. «Повторить»
  ставит ту же задачу снова в очередь; yt-dlp пытается докачать частичные файлы.
- «Удалить запись» удаляет историю и её лог; медиафайлы остаются.
  «Открыть папку» вызывает файловый менеджер ОС на компьютере сервера.
- История доступна отдельным пунктом меню, с фильтрами по статусу и пагинацией.
  В API есть `limit` (до 500) и `offset`; интерфейс показывает по 25 задач.

Путь и медиа-настройки фиксируются при создании задачи. Последующие изменения
корня и качества не перемещают старые задачи. Актуальные cookies и proxy
подхватываются при каждом новом запуске, чтобы можно было исправить авторизацию
и повторить ошибочную задачу. Параллельность 1–4, по умолчанию 1; уменьшение
лимита не отменяет уже запущенные задачи.

## Структура

```text
app/
  main.py                 роуты, lifespan, localhost/CSRF, загрузка cookies
  config.py               .env, корневые пути
  db.py                   SQLite, WAL, SQLAlchemy session
  models.py               Job, Setting
  schemas.py              Pydantic, URL, папки, шаблоны
  services/
    settings.py           постоянные настройки
    security.py           права 0600 / NTFS ACL для cookies
    ytdlp.py              аргументы CLI, метаданные, прогресс, завершение процессов
    worker.py             очередь, логи, отмена, восстановление
  templates/              Jinja2
  static/                 CSS, JavaScript, polling
data/                     БД, cookies.txt, logs/, блокировка экземпляра
downloads/                файлы по умолчанию
tests/                    unit, API, очередь с настоящим тестовым subprocess
.env.example
requirements.txt
desktop.py                окно управления и запуск упакованного yt-dlp
packaging/                PyInstaller spec, инструкция и лицензии компонентов
scripts/build_windows.py  сборка EXE
.github/workflows/         сборка и проверка Windows-релиза
```

При старте оставшиеся `running` переводятся в `error` с `interrupted`.
Ожидающие `queued` продолжают работу. При штатной остановке активные процессы
завершаются, задачи становятся `error`; пользователь может повторить их.
Логи сохраняются отдельно, до ~2 МБ на задачу с обрезкой старых строк;
API возвращает последние 64 КБ. Подробные метаданные, cookies, команды с
учётными данными и полные URL потоков в лог не записываются.

Каждый процесс получает защищённую временную копию cookies-файла, чтобы
параллельные yt-dlp не перезаписывали общий источник cookies. Копии удаляются
после завершения процесса; оставшиеся после сбоя — при следующем старте под
эксклюзивной блокировкой сервиса. Обновления cookies самим yt-dlp из временной
копии не переносятся в источник: истёкшую сессию обновляйте в настройках.

## Конфигурация окружения

Скопируйте `.env.example` в `.env`, если нужны другие пути. Значения:

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `KP_DATA_DIR` | `./data` | БД, cookies и логи |
| `KP_DOWNLOAD_DIR` | `./downloads` | Начальный корень загрузок до сохранения настроек |
| `KP_METADATA_TIMEOUT` | `180` | Таймаут метаданных в секундах |
| `KP_DEV_MODE` | `false` | Явное разрешение других HTTP(S) URL и экстракторов для разработки |

Dev-режим выключен по умолчанию, не включается из UI. Его не нужно включать
для кино.pub. Он расширяет сетевые назначения; используйте только с доверенными
локальными тестовыми данными. DRM и платный доступ сервис не обходит.

CDN-библиотеки соответствуют запрошенному стеку. Основная вёрстка, очередь,
формы и резервная диагностика работают через локальные CSS/JS и при
недоступности CDN. HTMX обновляет диагностику, Alpine управляет раскрывающейся
справкой; небольшая JS-программа опрашивает очередь раз в 2 секунды. Тестовый
загрузчик никогда не включается в рабочем приложении.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/`, `/settings` | Страницы |
| POST | `/api/metadata` | `{ "url": "https://kino.watch/item/view/123" }` |
| POST | `/api/jobs` | URL, title, quality, audio, subtitles, folder, filename_template, episodes |
| GET | `/api/jobs?status=done&limit=25&offset=0` | Список |
| GET | `/api/jobs/{id}` | Статус, прогресс и итоговые пути |
| GET | `/api/jobs/{id}/log` | Последние строки лога |
| POST | `/api/jobs/{id}/cancel` | Отмена |
| POST | `/api/jobs/{id}/retry` | Повтор ошибки/отмены |
| POST | `/api/jobs/{id}/open-folder` | Открыть файловый менеджер |
| DELETE | `/api/jobs/{id}` | Удалить завершённую запись и лог |
| GET, PUT | `/api/settings` | Чтение / полная замена настроек |
| POST | `/api/settings/cookies` | Multipart-поле `file` |
| POST | `/api/settings/cookies/header` | Cookie активной сессии и домен, опционально User-Agent; источник file включается автоматически |
| GET | `/api/health` | Наличие ffmpeg, версий yt-dlp, плагина и cookies-файла |

Все изменяющие запросы требуют заголовок `X-CSRF-Token` со значением
`<meta name="csrf-token">` главной страницы. Интерфейс делает это автоматически.
Токен меняется при перезапуске: обновите вкладку после рестарта. Запросы с
чужим Origin/Host или удалённого IP отклоняются; CORS не включён. Для внешнего
клиента сначала GET `/`, извлеките meta-токен, затем передавайте заголовок.
Swagger `/docs` удобен для чтения схем; изменяющие операции без заголовка
вернут 403.

Proxy опционален; MVP принимает HTTP(S)/SOCKS5 URL без логина/пароля. Произвольные
CLI-аргументы, настройки профиля браузера, загрузка чужого `info.json` и exec
не поддерживаются.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m yt_dlp --version
ffmpeg -version
```

Тесты изолируют SQLite, настройки, cookies и выходные файлы в `work/`.
Покрывают URL, path traversal, шаблоны, аргументы CLI, парсер прогресса,
редактирование настроек, cookies, localhost/CSRF, импорт и `/api/health`,
подпроцесс с прогрессом/результатом, отмену, повтор, ошибку, очистку секретов
из логов и восстановление очереди. Настоящий аккаунт не требуется.

Полная локальная проверка настоящими yt-dlp и ffmpeg (без аккаунта):

```powershell
.\.venv\Scripts\python.exe scripts/verify_local_pipeline.py
```

Скрипт генерирует короткое тестовое видео, поднимает временный HTTP-сервер
на loopback, включает dev-режим только в своём процессе и отдельной папке data,
проверяет метаданные, загрузку, прогресс, создание MKV и чтение ffprobe.
Тестовые cookies фиктивные и не передаются на внешние сайты. Отчёт и видео
остаются в отдельной подпапке `work/real-pipeline-*`.
Рабочая БД, cookies и dev-режим основного сервиса не меняются.

Результат проверки 24 октября 2026: **77 тестов прошли**, `pip check` без
конфликтов; реальная локальная цепочка yt-dlp → ffmpeg → MKV прошла.
Установлены yt-dlp 2026.10.21, плагин 0.1.1 и ffmpeg 9.0.2. Точные версии
Python-зависимостей записаны в `requirements.lock.txt`; для воспроизведения
окружения можно установить `pip install -r requirements.lock.txt`.
Starlette выводит предупреждение о будущей замене httpx в TestClient; на
результаты текущих тестов оно не влияет.

## Windows EXE и GitHub Releases

Сборка выполняется на Windows x64 с Python 3.12:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
.\.venv\Scripts\python.exe scripts/prepare_ffmpeg.py
.\.venv\Scripts\python.exe scripts/build_windows.py
.\.venv\Scripts\python.exe scripts/verify_windows_exe.py
```

`prepare_ffmpeg.py` получает конкретный Gyan FFmpeg 9.0.2, проверяет
закреплённый SHA-256 архива и копирует только нужные бинарники и лицензии.
Если FFmpeg уже установлен из того же дистрибутива, можно использовать
`scripts/prepare_ffmpeg.py --from-dir "C:\path\to\ffmpeg-9.0.2-full_build"`.
В приложение не попадают `.env`, рабочая БД, cookies, логи и скачанные видео.

Результат: `outputs/KinoPub-Local-Downloader.exe`, `SHA256SUMS.txt`,
`WINDOWS-README.txt` и `third-party-notices.zip`. Smoke-тест запускает именно
EXE с PATH без Python и системного ffmpeg, проверяет страницы, авторизацию
фиктивным файлом cookies, реальные subprocess yt-dlp и создание MKV из
локального тестового видео. Результат — `windows-exe-verification.json`.

После загрузки исходников в GitHub:

1. Откройте **Actions → Windows EXE → Run workflow** для пробной сборки.
   Результат будет в **Artifacts → KinoPub-Windows-x64**.
2. Для версии создайте и отправьте тег, например:

   ```bash
   git tag v0.2.0
   git push origin v0.2.0
   ```

3. Workflow соберёт EXE, запустит тесты и создаст **черновик Release** с файлами.
   Проверьте содержимое, исходники и лицензионные материалы компонентов,
   затем нажмите **Publish release**.
4. Пользователи открывают **Releases → Assets** и скачивают EXE.
   Кнопка **Code → Download ZIP** скачивает исходники, а не приложение.

Автоматическая сборка использует стандартный `GITHUB_TOKEN`; личный токен
не нужен. Сам workflow в GitHub ещё не запускался без репозитория.
Сборка не подписана сертификатом разработчика; проверяйте источник и
`SHA256SUMS.txt`, не отключая защиту Windows. Материалы сторонних компонентов
собираются отдельно; FFmpeg и плагин сохраняют свои лицензии.

Ручная проверка со своим аккаунтом:

1. На `/settings` все зависимости готовы, cookies-настройки сохраняются.
2. Ссылка на доступный фильм возвращает метаданные. Сериал показывает сезоны
   и серии, можно выбрать небольшой поднабор эпизодов.
3. Задача переходит `queued → running → done`, обновляются скорость/ETA/лог,
   MKV появляется в нужной папке и воспроизводится с выбранной дорожкой.
4. Активная загрузка отменяется, ffmpeg тоже прекращает работу; повтор
   возобновляет задачу. Удаление записи не удаляет скачанное видео.
5. При перезапуске очередь не зависает; прерванная задача содержит
   `interrupted`, ожидающие продолжают работу. Проверьте лимит параллельности.

Без действующих cookies и доступа к вашему аккаунту реальное скачивание
проверить нельзя. Диагностика проверяет наличие ffmpeg в PATH и загрузку
модуля плагина; она не подтверждает подписку, действительность cookies или
исправность конкретного ffmpeg-бинарника.

## Типовые проблемы

- **Не найден ffmpeg:** установите системный пакет и перезапустите терминал
  вместе с сервисом. `ffmpeg -version` должен выполняться в том же окружении.
- **Не установлен плагин:** запускайте pip и Uvicorn одним Python из `.venv`.
  `python -m pip show yt-dlp-kinopub` проверяет установку; `/api/health`
  дополнительно проверяет доступность модуля. Плагин закреплён на 0.1.1.
- **Cookies недоступны:** убедитесь, что выбрали нужный браузер и его профиль
  по умолчанию. Для нестандартного профиля используйте экспорт cookies.txt.
  На Safari могут понадобиться системные разрешения; Chrome может запрещать
  расшифровку. Обновите cookies своего аккаунта, затем повторите задачу.
- **Сайт отклоняет запрос / challenge / 401 / 403:** проверьте сессию,
  подписку и доступность сайта в браузере. Обход challenge/DRM/оплаты в сервисе
  не реализован. Изменения сайта могут потребовать обновления yt-dlp/плагина.
- **Качество/аудио отсутствуют:** они зависят от конкретного материала.
  Предпочтение аудио не гарантирует наличие дорожки во всех сериях.
- **403 после перезапуска:** обновите страницу для получения нового CSRF-токена.
- **Порт занят:** остановите предыдущий экземпляр, не запускайте второй воркер.
- **Папка не открывается:** на headless-системах нет файлового менеджера;
  итоговый путь доступен в GET `/api/jobs/{id}`.
- **Нет места:** освободите место, затем повторите задачу; `.part` остаются.
- **Windows: asyncio/тест зависает в sandbox:** требуется разрешение на
  локальные loopback-сокеты и создание дочерних процессов. Это нужно даже
  TestClient для внутреннего event loop, без обращения к kino.pub.

## Законное использование

Публикация в GitHub включает исходники и метаданные Git-коммитов. Для защиты
личного email используйте GitHub noreply в локальной конфигурации этого
репозитория. `.gitignore` исключает рабочие cookies, БД, логи, видео,
виртуальное окружение, `.env`, `work/`, `vendor/` и `outputs/`.
Пример cookies содержит только вымышленные значения.
Публичный отчёт проверки EXE содержит результаты и версии компонентов;
локальные пути, названия личных файлов, URL и данные аккаунта туда не включаются.

Используйте только собственный аккаунт, законно доступные материалы и загрузку,
разрешённую правообладателем, применимым законодательством и ToS сайта.
Активная подписка сама по себе не означает право распространять контент.
Не передавайте cookies, токены и скачанные файлы посторонним. Не используйте
сервис для обхода DRM, платного доступа или ограничений чужих аккаунтов.
